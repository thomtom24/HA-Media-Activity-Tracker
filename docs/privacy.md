# Data and privacy

The integration stores application labels/IDs, daily and hourly durations, session timestamps and tracking-mode/source changes in `.storage/media_activity_tracker.<entry_id>`. It does not intentionally store programme titles, but source labels may themselves contain identifying information. HA state/Recorder, automation messages and backups may retain copies independently. Activity reveals household routines. Restrict source and tracker entity access; the historical report checks both. Downloaded CSV files leave HA and should be protected. Diagnostic exports omit entity IDs and activity but logs may contain them.

Back up Home Assistant before upgrading. Never remove a config entry to upgrade it: removal deletes its history. Use the HA backup/restore facility to restore the whole installation, including config entries and storage, after corruption. For advanced manual recovery stop HA and restore the corresponding history file from a known-good backup using the same entry ID. Do not edit or overwrite corrupt files without a backup. Atomic writes and private file creation reduce risk but do not guarantee disk durability. The offline JSON backup/restore tool preserves full history. CSV exports aggregates only. From a checkout of this repository, run `python tools/history_backup.py export /path/to/config ENTRY_ID /path/to/backup.json`. Stop HA before restoring, then use `python tools/history_backup.py restore /path/to/config ENTRY_ID /path/to/backup.json --confirm-stopped`. This requires direct filesystem access, validates the same tracker ID and creates a .before-restore safety copy; move that copy to private storage when finished. Do not restore while HA is running. Pruning session details is irreversible without backup. Recorder and backups require separate deletion/retention controls.

Tracking conditions can indirectly disclose household activity through resulting tracking status and duration, even without exposing the condition entity ID. Only grant access to trackers whose inferred activity the user may see. The observed-day average excludes days with no observation but does not estimate full-day use; older history may lack coverage. Comparison windows require near-complete observation and may remain unavailable after downtime.
